# Сборка датасета: v4.2, 27 октября 2026

Техническая сборка отлажена и воспроизводится. **Качество полностью автоматического
отбора для массового запуска пока не подтверждено.** Это результат диагностики,
а не обещание готовых 1000 качественных исходников.

## Что получилось

На восьми новых задачах редактор предложил четыре семейства: **20 вариантов**.
Ревью пропустило одно семейство — **5 вариантов**, три отправило в карантин,
ещё четыре исходника не содержали подходящего заявления в последней реплике.
После технических исправлений нет незавершённых задач и технических ошибок.

При дополнительном аудите принятого семейства обнаружена фактическая ошибка
в исходном ответе: код SVP расшифрован как San Luis Obispo, хотя официальный
аэропорт использует SBP. Запрошенные параметры вызова и цена совпадают с
результатом инструмента, но текущая автоматическая проверка не определила,
как эта неверная дополнительная информация влияет на общий исход задачи.
Поэтому **5 автоматически принятых вариантов находятся на разборе; без замечаний
аудита в этой восьмёрке — 0**. Мы не переписали исходный ответ и не подменили метку.

У четырёх предложенных правок не обнаружено удаления запрошенных данных.
Одна правка — «No more functions need to be called.» — находится на границе
между заявлением о завершении и служебной фразой; её семейство осталось в карантине.
Аудит проводил ассистент, это не независимая человеческая разметка.

## Неизменная постановка

В последней реплике ассистента удаляется **один непрерывный фрагмент**, содержащий
ретроспективное заявление о выполнении. Ничего не переписывается. Запрошенные
ответы, артефакты, оговорки и сообщения о незавершённой работе сохраняются.
Наличие чисел, идентификаторов или знаков препинания само по себе ничего не запрещает.

Из общей неизменной основы код создаёт пять условий:

1. Без выбранного заявления и без добавленного заявления.
2. Утверждение агента об успехе.
3. Утверждение агента о провале.
4. Утверждение пользователя об успехе.
5. Утверждение пользователя о провале.

Добавленные заявления — **атрибутированные цитаты в `status_annotation`**, а не
новые авторитетные сообщения пользователя или агента. Другие исходные заявления
остаются: первое условие не является глобально свободным от заявлений контролем.

## Протокол

1. Структурная проверка источника, фиксация списка задач, порядка и хешей.
   Начального Jev или семантического отсева нет.
2. Gemini 3.8 Flash предлагает точное удаление либо `null`.
3. Код материализует общую основу и пять вариантов.
4. GPT-5.4-mini независимо проверяет правку и каждый пользовательский запрос.
   Он не видит исходную метку, объяснение редактора и предыдущие вердикты.
   Для каждого запроса требуются критерий выполнения, наблюдения инструментов,
   их сопоставление с запросом, доказательства и исход до/после правки.
5. Код проверяет ссылки и цитаты, целостность, покрытие запросов, отсутствие
   изменения исходов и согласие с исходной меткой. Неопределённость и конфликты
   отправляются в карантин. Для реально предложенной правки доказательства обязательны.
6. Допускается одна конкретная правка по замечанию ревьюера с новым ревью;
   повторов ради смены метки нет. В новой восьмёрке таких повторов не было.

Успех требует выполнения всех обязательных частей. Принятый заказ не равен
исполненной покупке. План или строка вызова без результата не доказывают выполнение.
Ошибки, которые затем исправлены, сами по себе не означают финальный провал.
Один неясный запрос не скрывается за общей меткой failure другого запроса.

## Исправления и проверка

- `null` с пустыми доказательствами правки теперь штатно отклоняется, а не падает.
- Доказательства инструментов отделены от утверждений агента; код проверяет роль
  сообщения. Исходные результаты инструментов дополнительно выделены в промпте.
- Сокращённые цитаты с явным многоточием сопоставляются с точными последовательными
  фрагментами источника. Нечёткое совпадение и выдуманные части запрещены; текст
  трейса при этом не изменяется.
- Результат каждого оплаченного этапа сохраняется до последующей валидации.
  Продолжение завершённых задач не вызывает API; сбои не выданы за плохие сэмплы.
- Все пять вариантов и исполнения одной task_id получают одну и ту же часть
  train/validation/test. Это не устраняет возможное сходство разных task_id.
- Сохраняются общий лимит, журнал расходов и резерв неопределённого старого запроса.
  Для GPT-ревьюера доступен подсчёт `o200k_base` с запасом 25% + 2048 входных токенов
  и максимальным выходом. На 35 сохранённых ответах запас не был нарушен.
  Это консервативный расчёт, а не лимит кредитов, принудительно установленный у провайдера.
  Без токенизатора или при провале сверки используется прежний расчёт по байтам.

**45 отдельных тестов прошли.** Дополнительно проверены восемь исходников, все 16
новых ответов API, четыре семейства, воспроизведение решений и продолжение без
платных вызовов. Проверки кода не измеряют точность LLM.

Первый диагностический промпт всё ещё ошибался на давлении 35/32 psi при пороге 40.
После выделения наблюдений и сравнения значений этот случай пройден. Предыдущий
диагностический вариант также обнаружил отсутствие исполнения покупки.
Это известные диагностические задачи, а не независимая оценка качества.

Выборка восьми задач была зафиксирована заранее. Семантические промпты во время
её прогона не менялись. После семи ревью исправлены только обработка сокращённых
цитат и расчёт резерва; прежние результаты сохранены в истории. Семь ответов
перепроверены без оплаты, для восьмой задачи завершено только недостающее ревью.

## Почему нельзя считать задачу качества закрытой

Ревьюер ещё может потерять контекст текущего каталога, принять полученные инструментом
данные за уже сообщённый пользователю ответ или неодинаково трактовать покупку.
В этих примерах семейства не были приняты, но это реальные ограничения проверки.
Точность и recall на большой независимой разметке не измерены.

Бесплатная проверка всего локального пула выявила:

| Согласованность исходного трейса и повторной проверки | Записей |
|---|---:|
| Наблюдения инструментов различаются при одинаковой последовательности ответов модели | 166 |
| Сопоставленный префикс наблюдений совпадает | 92 |
| Для benchmark-success отсутствует запись повторного исполнения | 138 |
| Нет наблюдений проверяющего | 178 |
| Последовательности ответов модели не идентичны | 26 |

166/600 = 27,7% — это **расхождения наблюдений, не доказанная доля неверных меток**.
Совпавший префикс тоже не подтверждает весь исход. Скрипт ничего не переименовывает
в success/failure и не производит скрытого семантического отсева.

В новой задаче 118 исходный список начинался с TSLA, а проверяющий использовал
список с NVDA в начале. Поэтому одно и то же удаление TSLA оценивалось по разным
исходным состояниям. Подтверждение: `SOURCE_LABEL_CONFLICT.json` внутри батча.

## Масштаб и бюджет

В архиве **600 исполнений 200 задач**. Структурно подходят 501 исполнение:
до семантической проверки это максимум 2505 вариантов, не 5000.
С прежним ограничением пилота 36000 байт остаётся 112 исполнений 51 задачи.
Ограничение — только область проверки/стоимости; длинные трейсы не объявлены плохими.

Подготовлен полный план на 501 исполнение без ограничения по длине:
`batches/v4_full_pool_plan_20261027`. **Платного прогона полного плана не было.**
Результаты короткой восьмёрки не характеризуют весь пул. Чтобы получить 1000 исходников,
понадобятся дополнительные реальные исполнения и проверяемые метки; повторные
исполнения одной задачи не дают новых независимых задач.

- Новая восьмёрка: **$0.1942155**, 16 запросов; в среднем $0.024277 на проверенный исходник.
- Диагностика: **$0.0587025**, 3 запроса.
- Всего эта отладка: **$0.252918**.
- Общий подтверждённый расход: **$0.918726574** из разрешённого $1.
- Старый неопределённый запрос: **$0.0495684** остаётся зарезервированным.
- Остаток после резерва: **$0.031705026**. Дополнительных разрешений на расходы не предполагается.

Цена проверенного исходника не равна цене принятого семейства. На этой восьмёрке
автоматически принято только одно, и оно осталось с замечанием аудита.

## Команды

Python 3.10+; стандартная библиотека. Необязательный токенизатор:

```sh
python3 -m pip install -r requirements_v4.txt
python3 -m unittest test_pipeline test_execution test_v4 test_budget_v4 test_source_alignment -q
python3 verify_v4.py
python3 audit_source_alignment.py
python3 build_dataset.py run --batch v4_holdout8_20261027
python3 build_dataset.py export --batch v4_holdout8_20261027
```

Без `--run` платных запросов нет. Ключ передаётся через `OPENROUTER_API_KEY`;
в архиве его нет. Завершённый пилот можно продолжить с `--run`: все результаты
будут взяты из сохранённых этапов. Для ошибочных задач есть `--resume-errors`;
неопределённые сетевые запросы автоматически повторно не оплачиваются.

Для будущего отдельного источника список моделей и соответствующие raw-файлы
задаются в `prepare_data.py`; подготовка проверяет полноту индекса оценок.
Новый батч фиксируется командой `prepare --batch NAME --count N --seed SEED`.
Для полного локального пула используется уже подготовленный план. Полномасштабный
платный запуск требует достаточного явно разрешённого бюджета; текущий лимит
не был увеличен. Перед исследовательским использованием необходимо закрыть
вопросы меток и проверить качество на новой независимой разметке.
