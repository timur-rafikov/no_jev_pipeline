# Сводка пилота: судья, утверждения и доказательства

Вопрос: как маленький судья без рассуждения сочетает видимый исход трейса и вставленное
утверждение «задача выполнена / не выполнена» (источник: агент, пользователь, инструмент).
Данные: 46 трейсов BFCL, исход виден в тексте (23 успеха, 23 провала, ручная разметка, агенты
уравнены). Модели: Qwen3-14B и Qwen3-32B, один проход, лог-шансы Yes/No. Только два размера.

## 1. Данные и метки
- Метка BFCL `valid` ненадёжна: из 25 «провалов» пилота 8 на деле выглядят успешными, из 25 ещё
  11 принимали все 7 прогонов судьи. Часть провалов тихая (нет результатов, число не сходится).
- Поэтому набор пересобран вручную по видимости исхода (`visible_pilot/`): из 501 исполнения
  прочитано 83 кандидата, 56 громких провалов; нужный пул мал (≈100 сбалансированных на старой метке).
- Без утверждений судья на этом наборе работает: AUROC 0.98–0.99, принимает 100% успехов и 8.7%
  провалов (14B и 32B одинаково). Прежняя «слепота» была шумом меток и тихими ошибками.

## 2. Поведение: утверждение против факта
| трейс → утверждение | 14B: Δ лог-шансов / смен решения | 32B: Δ / смен решения |
|---|---|---|
| успех → «успех» | +2.4 / 0 из 23 | +1.3 / 0 из 23 |
| успех → «провал» (ложное) | −30…−37 / 21–22 из 23 | −5.8…−7.4 / 20–22 из 23 |
| провал → «успех» (ложное) | +9…+11 / 3–6 из 23 | +3.2…+4.2 / 3–5 из 23 |
| провал → «провал» | −12 / 2 из 23 | −3…−3.5 / 1–2 из 23 |

1. Асимметрия: ложное «провал» почти всегда ломает верный успех, ложное «успех» редко спасает провал.
2. Источник: tool чуть сильнее agent и user для «провала» (14B: −37 против −30, интервалы не
   пересекаются; 32B: −7.4 против −6.7/−5.8, пересекаются). Агент и пользователь не различаются.
3. Атрибутированная пометка (quoted) действует немного сильнее, чем сообщение в диалоге (inline).

## 3. Механистика (последний токен, где выдаётся Yes/No)
- Утверждение читается рано и одинаково для всех источников (проба ≥0.9, перенос на неизвестный
  источник ≈1.0; может быть лексическим кодом, строки утверждений одинаковы).
- Факт представлен и при противоречащем утверждении: проба на исход на токене конца утверждения
  0.90–0.96 в «лживых» строках (контроль перестановкой 0.46–0.50).
- Слияние с фактом в позиции ответа поздно и резко: патчинг последнего токена даёт 0 до слоя ~20 (14B)
  / ~40 (32B), затем ≈0.8–1 за 6–12 слоёв. Направления «истина» и «утверждение» почти ортогональны
  (косинус 0.1–0.26) до слияния, затем сливаются в ось «Да/Нет» (косинус 0.9). Steering этих
  направлений неотличим по эффекту и работает только после слияния.
- SAE: после слияния признаки «утверждение» и «истина» общие (38 из 50 лучших признаков пересекаются);
  до слияния отдельных признаков нет (распределённый код).

## 4. Как это масштабируется (14B → 32B, две точки)
| | 14B (40 слоёв) | 32B (64 слоя) |
|---|---|---|
| доля смен решения от ложного «провала» / «успеха» | 21–22 / 3–6 из 23 | 20–22 / 3–5 из 23 |
| размер ложного «провала» к разрыву факта без утверждения | ≈0.75 | ≈0.55 |
| утверждение читается (проба ≥0.9) | 45% глубины | 34% |
| слияние с фактом (патчинг ≥0.8) | ≈70% глубины | ≈81% |
| масштаб лог-шансов (разрыв «факт») | 40.8 | 11.4 |

- Не масштабируется: доверие к утверждению. Доли смен решения те же, асимметрия та же; с ростом
  размера поведение не стало ближе к «судье по фактам».
- Масштабируется: калибровка (логиты в 3.5 раза мельче), относительный размер утверждения чуть
  меньше, слияние позже по глубине и резче.
- Оговорка: две точки, одна семья, одни и те же 46 трейсов. Это не кривая масштабирования.
  ≤4B (то, что нужно задаче) не измерен. Старый прогон MiniCPM5-2B (почти всегда «Да») шёл на
  другом наборе с метками BFCL и несравним.

## 5. Ограничения
46 трейсов, один разметчик, судья без рассуждения, одна позиция для проб. Проба на «исход» могла
декодировать коррелирующие признаки трейса. Направления steering считались на тех же данных.
Патчинг только последнего токена. Результаты на последнем слое патчинга и steering не читаются
(финальная нормализация). SAE не размечались. Исходные утверждения внутри трейса не удалялись.

Подробности: `claims_pilot/README.md`, данные: `claims_pilot/out/` (14B) и `out32/` (32B).
